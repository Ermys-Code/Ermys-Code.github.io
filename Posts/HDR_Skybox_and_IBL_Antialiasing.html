HDR Skybox and IBL Antialiasing

  • Solo work
  • Engine
  • Graphics

Overview

In my Master's Degree project Bound by Death, we wanted to upgrade our previously IBL system so it become more noticeable.

To acomplish this, we wanted to add support for HDR textures as skybox, because before we only supported cubemaps.

Problems and objectives

For this task, all we needed to do was convert the HDR images that use in equirectangular map to a cubemap and use this cubemap as source for the already existent skybox pipeline.

I also took the oportunity to implement antialiasing on the Specular IBL to minimize aliasing artifacts.

Technical implementation

The first thing I did was modify the Skybox class to store a reference to a HDR texture.

Then I created a new render pass that gets executed at he start of the Skybox initialization, and this pass takes the HDR texture stored in the Skybox and renders a cubemap with 11 mip levels that is stored where the previous skybox cubemap was configured, maintaining the exisiting pipeline.

To convert from equirectangular map to cubemap, I did the following:

  1. Convert the position of the pixel to a direction using the camera's view projection.
  2. Calculate X value of the UV coordinates for this pixel using atan2 on direction.Z and direction.X.
  3. Calculate Y value of the UV coordinates for this pixel using asin on direction.Y.
  4. Normalize both X and Y values to 0-1 range.
  5. Flip both axes to get the correct orientation.
  6. Sample the HDR skybox texture with the calculated UV.

With the HDR skybox working, I started implementing the Specular IBL Antialiasing by modifying the Irradiance Skybox Pass and the Prefiltered Environment Skybox Pass.

In both pixel shaders I use the Normal Distribution Function to calculate the probability density function based on the roughness and the dot product between the normal and the half vector.

Then I compute the mip level to use for each sample on the :

  1. Get the probability of each sample using the number of samples and the probability density function previously calculated.
  2. Get the probability of each texel using the width of the viewport that the shader recives.
  3. Do log2 of the probability of each sample divided by the probability of each texel, and multiply the result by 0.5, if the result is grater than 0 that's the level to sample, if not, 0 is the level to sample.

Challenges and problem-solving

I encountered one major issue during development:


Equirectangular to cubemap conversion error.

When converting from equirectangular to cubemap, the rendered cubemap apeared totally distorted in the X axis.

After a bit of debugging, I realized that I had an error when normalizing to 0-1 range the X value of the UVs, where I was missing some parenthesis, I fixed the mathematical operation and it worked fine.
